## 1. 役割

Bronzeは、DataSpiderからGCSに届いたCSVを、取得回ごとに全行・全列そのまま保持する。Silverでの解釈・再検証に使う元データを残すことが目的。

| 処理 | Bronze | Silver |
| --- | --- | --- |
| 元の行・列 | すべて保持（0時間・NULL・重複行も残す） | 必要な入力を選ぶ |
| 型 | 取得元の型に対応する型で格納 | 分析用に整形（作業日のDATE化など） |
| 取得回 | 回ごとに追加保存し、過去を上書きしない | 利用する取得回を決める |
| 承認・修正の意味付け、分類・統合・集計 | 行わない | 行う |

## 2. 決定事項

| 論点 | 方針 | 理由 |
| --- | --- | --- |
| 取込方式 | ビュー → DataSpider（CSV）→ GCS → GCS外部テーブル＋Dataform → Bronze。BQLoadは不採用 | 業務キーで絞り込まず、届いた全行を保持するため |
| テーブル構成 | bronze.oks02／oks07／oks10の3テーブル。Bronzeでは統合しない | 取得元ごとの内容を分けて残すため |
| 型 | 取得元対応型（全列STRINGにしない）。keijo_dateはSTRINGのまま | 取得元仕様に合わせて読み込める前提 |
| NULL | 取得元の必須「○」はNOT NULL、他はNULLABLE。補完しない | 取得元の必須項目を引き継ぐため |
| 管理列 | _batch_id・_loaded_at・_source_file・snapshot_date（すべてNOT NULL） | 元ファイルと取込処理を追跡するため |
| 取込日 | snapshot_date＝DATE(_loaded_at, 'Asia/Tokyo')。作業日・抽出日とは別物 | 遅延時も実際の取込日を記録し、補正しない |
| 物理設計 | snapshot_dateの日次パーティション。当初クラスタリングなし。自動削除期限なし（GCSの保存期限は別事項） | 過去の取得回も残して再検証するため |
| 取込済み判定 | work/のCSVだけを対象に、ファイルのbasenameで判定して追加。成功後はarchive/へ移動 | MERGE・行の絞込みをせずに二重取込を防ぐため |
| 0件CSV | 届かない前提。0件CSVの完了管理は対象外 | 確定した設計前提 |
| 検査 | 件数一致はassertion。重複は記録のみで、一意性assertionは設けない | 業務キーが未確定のため、重複をエラーと断定しない |
| 管理列の実装 | 共有されたG会社案件を参考にする（取込日は日本時間、MERGE・行の絞込みは採用しない） | — |

## 3. 誤解しやすい点

- 「全行保持」は届いたCSVの全行という意味で、取得元システムの全件ではない。
- _batch_idは3ビュー共通の取得回IDでも、行の一意キーでもない。抽出時点や新旧も保証しない。
- 行が届かなくなったこと・0工数を、業務上の削除・取消と断定しない。
- 原因不明の重複行（OKS02の複合候補、OKS10の履歴ID）をDISTINCT・合算で消さない。

## 4. 未確定事項

B-01（CSV抽出条件）は未確認のまま保持するが、Bronze設計を進める前提条件にはしない。ビュー間の違いの扱いはSilverで検討する。

| ID | 論点 | 確定条件 | 確認先 | 優先度 |
| --- | --- | --- | --- | --- |
| B-00 | DataSpiderでどうデータを持ってきてもらうか | — | DataSpider・取得元担当 | — |
| B-01 | ビュー別CSVの入力条件 | 対象期間・状態・抽出条件・出力契機・頻度・更新なし時の扱いが明記される | DataSpider・取得元担当 | 高 |
| B-02 | 管理列の値の生成・付与 | _batch_id・_loaded_at・_source_fileの具体的な生成・付与方法を定義 | 取込実装担当 | 高 |
| B-03 | 業務識別・重複・取消の意味 | Silverの採用・統合設計の前に確認（Bronzeは元の行を削らず保持） | 取得元担当 | 高 |
| B-04 | CSV件数の受渡し・保存 | 欠落も含めた取込対象ファイルと件数の参照・保存方法を定義 | DataSpider・取込実装担当 | 高 |
| B-05 | 物理配置・権限・検査運用 | プロジェクト・リージョン・権限・異常時対応・スキーマ変更対応を定義 | 利用・実装担当 | 中 |

このほか、フルリフレッシュ時の扱い、取込とarchive/への移動の間に失敗した場合の制御は後工程で定義する。
